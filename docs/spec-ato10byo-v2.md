# 「あと10秒」仕様書 v2（Unity実装向け）

2026-11-26 版 ・ ベース：仕様書 v1（2026-11-24）＋ プロトタイプ `あと10秒.html`

> v1からの変更点は「1. 確定事項」と「9. Unity実装仕様」。ルールや謎の中身は v1 から変わっていません（プロトタイプの実装に合わせて数値を補正した箇所は「8. プロトタイプとの差分・補足」に記載）。

## 仕様意図

10秒で爆発する爆弾を、謎を解いて相手に押し付け合う2人対戦。会場展示で、通りがかりの人が30秒で理解でき、観客が横で見ても盛り上がる「ホットポテト型 謎解きアクション」にする。

- 序盤は2秒、終盤でも6秒ほどで解ける、考え込まない謎だけを使う。
- 焦りが敗因になる（ミスすると −2秒）。
- 待つ側も気が抜けない（相手が切った線を覚えておく謎がある）。

## 3. ルール

### 3.1 タイマーと爆弾の受け渡し

- 爆弾を受け取った瞬間に10.00秒から減り始める（0.01秒単位で表示）。
- 回答中・スタン中も減り続ける。爆弾が飛んでいる0.4秒間は減らない。
- 第1パスは、ラウンド開始演出（約1.8秒）が終わってから減り始める。
- 受け取るたびに「あと10秒！」の短いボイスを鳴らす。

### 3.2 回答したときの処理

| 結果 | 処理 |
| --- | --- |
| 正解 | 爆弾が0.4秒かけて相手に飛ぶ。届いたら残り時間を戻し、新しい謎を出す |
| 不正解 | 残り時間 −2.00秒、0.5秒の入力停止（スタン）。配線は切った線が消えて残り3本。暗号・順番スイッチは入力が消えて最初からやり直し。謎の答えは変わらない |
| 時間切れ | 0以下で即爆発。不正解で引かれて0以下になった場合も同じ |

### 3.3 先攻と勝敗

- 第1ラウンドの先攻はランダム。第2ラウンド以降は前ラウンドの勝者（仮決め）。
- 2ラウンド先取で勝利（設定で3ラウンド先取に変更可）。引き分けなし。

### 3.4 パス10回目からの時間短縮（仮決め：あり）

- 受け取りごとの持ち時間 ＝ `max(SHRINK_MIN, HOLD_TIME − (n − SHRINK_FROM_PASS + 1))`（n は何回目の受け取りか）。
- 例：10回目=9秒、11回目=8秒、…、15回目以降=5秒。
- 画面に「あと9秒！」のように、その回の持ち時間を表示する。

## 4. 操作

使うのは、上下左右の4本の配線に対応する4方向キーと、解除キーだけ。

| 操作 | P1 | P2 | ゲームパッド |
| --- | --- | --- | --- |
| 上／下／左／右 | W／S／A／D | ↑／↓／←／→ | 十字キー／左スティック |
| 解除を始める | Q | 右Shift | Y（上のボタン） |
| 決定（タイトル等） | Space | Enter | A（下のボタン） |
| タイトルに戻る | Esc | Esc | Start |
| クイックテキスト（待機中のみ。4.1） | 方向キー W／A／S／D を押し続けて、離す | 方向キー ↑／←／↓／→ を押し続けて、離す | 十字キー／左スティックを倒し続けて、離す |

- キーを押した瞬間で判定。長押しは無視する。
- 爆弾を持っていないときの入力は、爆弾の入力としては無視する（先行入力なし）。待機中の方向キーはクイックテキスト（4.1）に使う。
- 爆弾が届いてから0.15秒は入力を受け付けない（連打の誤爆防止）。
- スティックは傾き0.6超で1回の入力、0.3以下に戻るまで次を受け付けない。
- **会場展示ではゲームパッド2台を主役にする**。キーボード2人同時押しは機種により取りこぼすため、保険扱い。

### 4.1 クイックテキスト

待機中（爆弾を持っていない）のプレイヤーが、キー1つの操作で、頭上の吹き出しに定型文を出す機能。残り時間にも爆弾の入力にも関わらない。

| 項目 | 内容 |
| --- | --- |
| 出し方 | 待機中の側が方向キーを押し続けると、0.2秒後にキャラの上に円形の候補（上・下・左・右の4つ）が出る。押している方向の扇が黄色になり、キーを離すと、その方向の文が頭上の「待機中」の吹き出しに出る。0.2秒より短く押して離したときも、その文が出る |
| 選ぶ方向 | 2つ以上のキーを押しているときは、あとから押したキーを選ぶ。1つ離すと、残っているキーに戻る。全部離したときに、最後に選んでいた文を出す |
| 取り消し | 方向キーを押している間に解除キー（Q／右Shift／パッドのY）を押すと、候補を閉じて、キーを全部離すまで何も出さない |
| 表示時間 | 1.5秒（`QUICK_TEXT_TIME`）で「待機中」に戻る。続けて出すと置き換わる（連打の制限はない） |
| 文（初期） | 上＝W（↑）「いくぞ！」、下＝S（↓）「ざんねん〜」、左＝A（←）「まだまだ！」、右＝D（→）「ナイス！」。文は ScriptableObject（`UiQuickTextSet`）で書き換えられる |
| 使えない場面 | 爆弾を持っているとき、相手が解除中のとき、ラウンド開始のバナー・爆発・リザルトの間。爆弾を受け取った瞬間は、候補も文も消えて「あとN秒！」に戻り、押していたキーは爆弾の入力にならない。爆弾が飛んでいる間は、両方使える |
| CPU | 待機中に、5〜11秒おきにランダムな1文を出す |

## 5. 画面構成

- 画面は 1920×1080。インゲームのモックと、爆弾のラフに合わせる（配置の詳細は `Assets/_Project/Scripts/Matsushita/UI/README.md`）。
- 上：左に「戻る」（Esc でタイトルへ）、中央にラウンド（R1）、右にラウンド内のパス回数と難易度（1〜4）。残り時間は上には出さず、爆弾の中のタイマー液晶に出す（「05:00」の形）。
- 中央に爆弾を1つ大きく表示（640×640）。爆弾の中は、ひし形ボタン4つ（上・左・右・下。色は配線の色。暗号・順番スイッチのときはボタンに文字や記号が入る）、中央の赤いランプ、その下のタイマー液晶、下半分の口の形の液晶（謎の文章と、解除の条件・状態・解除ボタン）。配線は、各ボタンから爆弾の外側へ伸びる。
- 導火線：爆弾の口金から上へ出て、持っている側のキャラの横まで伸び、先に火花が付く。残り時間に比例して、火花が爆弾へ進みながら短くなり、0秒で爆弾に届いて爆発する。持ち主が変わると、反対側に10秒分の長さで伸び直す。時間短縮のときは、その回の持ち時間を全長とする。
- キャラは、爆弾の左右に1人ずつ立つ（P1が左、P2が右）。頭上の吹き出しが、持っている側は「あとN秒！」、持っていない側は「待機中」（クイックテキスト（4.1）を出している間は、その文）。CPUが考えている間は「…」。爆弾が相手に渡るときは、導火線が消え、中央の爆弾が小さくなりながら山なりに0.4秒で相手のキャラへ飛ぶ。
- 下に3つの帯：左に「P1」と勝ち星、中央にギミック名、右に勝ち星と「P2」（CPU対戦のときは「COM」）。
- 前に切られた線は画面に残さない（記憶の謎のため）。
- ボタンには色名の頭文字（赤・青・黄・緑）を書く。文字と色の食い違いの謎では、配線側の文字は常に配線の色を表し、謎の文章だけをひっかけにする。
- 残り3秒以下：タイマーが赤くなり、爆弾が小刻みに揺れ、導火線の火花が速くちらつく。持っている側は、画面の端の赤い帯が点滅し、キャラが焦り顔になる。

### 爆弾の属性（パスごとに作り直す）

| 属性 | 内容 |
| --- | --- |
| 配線 | 赤・青・黄・緑の4本を上下左右にランダム配置 |
| シリアル番号 | 10〜99。表示のみで、謎の答えには使わない（T4 はラリー回数を使う） |

## 6. ラウンドごとのギミックと謎

### 6.1 ギミック

| ギミック | やること | 入力回数 | 登場 |
| --- | --- | --- | --- |
| A 配線を切る | 正しい線を1本切る | 1回 | 第1ラウンド（固定） |
| B 暗号を入れる | 3文字の暗号を解いて入力 | 3回 | 第2〜4ラウンド（ランダム順） |
| C 順番スイッチ | 4つのスイッチを正しい順に全部押す | 4回 | 第2〜4ラウンド（ランダム順） |
| E 同時押し | 問題に合う2〜3個のボタンを、0.20秒以内に同時に押す（クリックは1.00秒）。謎は S1 色指定・S2 色混ぜ・S3 同じ記号・S4 足して10・S5 3つ同時 | 1回（2〜3個同時） | 第2〜4ラウンド（ランダム順） |
| D タイミング停止 | 色が切り替わるランプを正しい色で止める | 1回 | 余裕があれば |

- 3本先取で第4ラウンド以降に入ったら、パスごとにギミックがランダムに変わる「ミックスラウンド」。
- ラウンド開始時に「今回の爆弾：暗号ロック式」のようにギミック名と一行説明を出す。
- B・Cは入力済みの文字を画面に表示し、どこまで合っているか分かるようにする。

### 6.3 難易度の段階

パス回数はそのラウンド内の通算。各段階は書かれた種類から均等に選ぶ。同じ種類は3回連続で出さない。生成した謎は、正解が必ず一意になることを確認してから出す。

| 段階 | パス回数 | A 配線 | B 暗号 | C 順番スイッチ |
| --- | --- | --- | --- | --- |
| 1 導入 | 1〜2 | T1 | B1 | C1 |
| 2 慣れ | 3〜4 | T1・T2・T7 | B1・B4 | C1・C3 |
| 3 ひっかけ | 5〜6 | T2・T3・T4・T8 | B2・B3・B4 | C2・C3・C4 |
| 4 本番 | 7〜 | T3〜T8 | B2・B3・B5 | C2・C4・C5 |

目安：パス8回前後で決着する難しさ。人同士のテストで調整する。

## 7. 解除（ひらめき謎）と CPU

### 7.1 解除

- 使える条件：爆弾を持っていて、スタン中でなく、パス5回目以降。1ラウンド1人1回。
- 解除を始めたらキャンセル不可。残り時間は減り続ける。
- 4択（上下左右に選択肢）。正解で即ラウンド勝利、不正解で即爆発。
- 演出：画面を暗くして、相手（待機側）のキャラの近くに「解除中！」と大きく出す。
- 表示：解除の条件と状態（パス5回目から使える、使用済み、挑戦中）は、爆弾の液晶の下段に表示する。使えるときは、同じ場所に解除ボタンが出る。
- 問題は15問（同じ試合では同じ問題を出さない）。

### 7.2 CPU対戦

正解を知っている前提で、考える時間と正答率だけで動かす。実際に謎を解く処理は作らない。

| 項目 | やさしい | ふつう | つよい |
| --- | --- | --- | --- |
| 1入力あたりの考える時間 | 1.8〜2.6秒 | 1.2〜1.8秒 | 0.7〜1.2秒 |
| 段階ごとの追加時間 | +0.6秒 | +0.4秒 | +0.3秒 |
| 1入力あたりの正答率 | 80% | 90% | 97% |
| 解除を使う条件 | 使わない | 段階4で20% | 段階4で40% |
| 解除の正答率 | — | 50% | 70% |

- B・Cの2文字目以降は0.3秒間隔で入力。考えている間はキャラの頭上に「…」を出す。
- **展示での使い方**：操作なしで一定時間（目安30秒）経ったらタイトルに戻る。タイトルで放置されたらCPU同士のデモ表示（余裕があれば）。

## 8. プロトタイプとの差分・補足

プロトタイプ（`あと10秒.html`）を読んで確認した、v1 の文章とは違う／v1 に書かれていない点。Unity版はプロトタイプの挙動に合わせる。

| 項目 | v1 の記載 | プロトタイプの実装 |
| --- | --- | --- |
| ラウンド開始演出 | 約1.5秒 | 1.8秒（`INTRO`） |
| 爆発後の表示 | 記載なし | 2.0秒（`BOOM`）のあと次ラウンド／リザルト |
| 受け取り時のボイス | 「あと10秒！」 | その回の持ち時間を読む（「あと10秒」「あと9秒」…）。時間短縮が有効なとき、ボイスは10〜5の6種類が必要 |
| 難しさ段階 | パス1〜2／3〜4／5〜6／7〜 | 同じ（`stageOf`） |
| 先行入力 | 受け付けない | 同じ。受け取り直後0.15秒とスタン中も無視 |
| CPU戦のキー | 記載なし | どちらのキーセットでもP1を操作できる。解除は P2 の `/` キーでも可 |
| 手作り問題の量 | 解除15問 | 連想16、五十音8組、時間7組、大きさ6組、解除15問 |
| 解除の正解位置 | 選択肢をシャッフル | 先頭の選択肢が正解で、並びを毎回シャッフルしてから上下左右に割り当て |
| T4 の条件 | シリアル番号（偶奇／50以上／各桁の和） | ラリー回数（偶奇／3の倍数／8回目以降）。画面中央上に「ラリー N回目」を表示する |
| ゲームパッド | 対応 | 未実装（Unityで新規） |
| ギミックD | 余裕があれば | 未実装 |

## 9. Unity実装仕様

### 9.1 使うもの

- Unity 6000.6.7f1、uGUI（`com.unity.ugui` 2.0.0）、Input System（`com.unity.inputsystem` 1.20.1）。**どれも導入済みで、パッケージの追加は不要**の見込み。

### 9.2 シーン

チーム開発の注意として、同じシーンを複数人で同時に編集しない。UIパーツ（BombView、PlayerPanel、Banner、Result）はプレハブにして、プレハブ単位で作業する。

### 9.3 スクリプト構成（案）

ゲームのルールと謎の生成は、MonoBehaviour に依存しない普通の C# クラスにする。画面と入力は MonoBehaviour。こうするとルールをテストで確かめやすい（プロトタイプで「18種類を各300回生成して正解が決まることを確認」した検証を、そのまま EditMode テストにできる）。

| フォルダ | クラス | 役割 |
| --- | --- | --- |
| `Scripts/Core` | `GameConfig`（ScriptableObject） | 「調整用パラメータ」の値を持つ |
| | `MatchState` / `RoundState` | 勝ち星、パス回数、先攻、残り時間、解除の使用済みなど |
| | `MatchController`（MonoBehaviour） | フェーズ進行（intro→hold→flight→boom）と勝敗 |
| `Scripts/Puzzle` | `Puzzle` | 種類、表示テキスト、4方向のラベル、正解の入力列 |
| | `IPuzzleGenerator` と T1〜T8、B1〜B5、C1〜C5 の各クラス | 謎の生成。正解一意の確認を含む |
| | `PuzzleSelector` | 段階とギミックから種類を選ぶ。3回連続禁止、T8の出題条件 |
| | `PuzzleDatabase` | 手作り問題（JSON）の読み込み。同じ試合で重複させない |
| `Scripts/InputControl` | `PlayerInputReader` | Input System から「上下左右・解除」を1回入力として出す（スティックのしきい値処理を含む） |
| `Scripts/Cpu` | `CpuBrain` | 考える時間と正答率で入力を出す |
| `Scripts/UI` | `BombView`、`PlayerPanel`、`BannerView`、`ResultView` | 表示 |
| `Scripts/Audio` | `AudioManager` | 効果音・BGM・ボイスの再生 |

### 9.4 データ

- 手作りの謎は問題文だけで素材ではないので、公開側（このリポジトリ）に置いてよい。形式は v1 の JSON（`gimmick` / `type` / `text` / `items` / `choices` / `answer`）のまま `TextAsset` として読む。置き場所は `Assets/Resources/` 配下を想定。
- 調整用パラメータは `GameConfig` に集約。

| 名前 | 初期値 | 内容 |
| --- | --- | --- |
| `HOLD_TIME` | 10.00秒 | 受け取ったときの持ち時間 |
| `MISS_PENALTY` | 2.00秒 | 不正解で減る時間 |
| `STUN_TIME` | 0.5秒 | 不正解後に入力できない時間 |
| `FLIGHT_TIME` | 0.4秒 | 爆弾が飛んでいる時間 |
| `ARRIVE_LOCK` | 0.15秒 | 受け取ってから入力を受け付けない時間 |
| `INTRO_TIME` | 1.8秒 | ラウンド開始演出 |
| `BOOM_TIME` | 2.0秒 | 爆発演出 |
| `ROUNDS_TO_WIN` | 2 | 試合に勝つためのラウンド数（3も可） |
| `STAGE_PASSES` | 1・3・5・7 | 各段階が始まるパス回数 |
| `DEFUSE_MIN_PASS` | 5 | 解除が使えるパス回数 |
| `SHRINK_FROM_PASS` | 10 | 持ち時間を減らし始めるパス回数（無効にもできる） |
| `SHRINK_MIN` | 5.00秒 | 持ち時間の下限 |
| `LAMP_INTERVAL` | 0.6秒 | Dのランプが色を変える間隔 |
| `IDLE_RETURN` | 30秒 | 展示用：無操作でタイトルに戻る |
| `QUICK_TEXT_TIME` | 1.5秒 | クイックテキストを吹き出しに出しておく時間 |
| `QUICK_TEXT_WHEEL_DELAY` | 0.2秒 | 方向キーを押し続けてから、円形の候補が出るまで |

### 9.5 注意点

- タイマーは `Time.deltaTime` で減らし、`Update()` に重い処理を書かない。謎の生成は爆弾を受け取った瞬間に1回だけ行う。
- 「受け取りから0.15秒」「スタン0.5秒」「飛行0.4秒」は、フェーズごとの経過時間で管理する。
- 爆発・時間切れ・解除失敗は、どれも「ホルダーの負け」に1本化する。解除成功は「ホルダーの勝ち」。
- 画面の色の見分けがつきにくい人向けに、配線には色名の頭文字を必ず併記する。

## 10. 開発の優先順位

| 段階 | 内容 |
| --- | --- |
| 1 最低限遊べる | 2人操作、ギミックA（T1・T2）、持ち時間リセット、爆発と勝敗、2本先取 |
| 2 謎を増やす | Aの残りの謎、難易度の段階、不正解のペナルティ |
| 3 ギミック追加 | BとC、ラウンドごとの割り当て |
| 4 解除とCPU | 解除、CPU対戦（ふつうだけでも可） |
